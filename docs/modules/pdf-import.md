# PDF Batch Import

> Rasterise exam question / solution PDFs, detect per-question regions with a vision LLM (optionally CV-assisted), review and edit bounding boxes, then crop and create `QUE` / `SOL` IMG assets — or, in Generic Extraction mode, download labelled crops as a ZIP.

The tool lives under Admin Operations (after Question Ingestion). `app/pdf_import.py` owns staging, rasterisation, detection, cropping and commit; the atomic disk + DB write reuses `app/batch_image_gen.py`. One page image goes to the LLM per call, which keeps small local models (e.g. `qwen3vl4b`) inside their context window.

### SSE contract

`data: {json}\n\n`; `type` ∈ `job` (first; carries `job_id`) / `info` / `success` / `skip` / `error` / `done`, each with `message` and usually `current` / `total`.

- `detect`: each page emits `success` (or `error`) with `page: {kind, index, boxes, raw?}`; `done` carries `stats: {pages, questions}` and the full `plan`. A pre-flight failure (no pages, method needs NumPy) yields `error` then `done`.
- `split-detect`: per parent crop `success` / `skip` / `error`; `done` carries the rewritten `plan`.
- `commit`: per group `success` / `skip` / `error`; `done` carries `stats: {questions_created, assets_written, skipped, errors}`.
- Cancellation: per-job `threading.Event` in `_PDF_CANCEL` (guarded by `_PDF_LOCK`), checked between pages / questions; a cancelled run still emits `done` with partial stats and plan.

## Business rules / invariants

### Flow (3-step UI)

```
Step 1 stage (upload/pick + rasterise) -> Step 2 [optional detect SSE] + bbox editor -> Step 3 commit (SSE) or ZIP
```

- **Step 1 — Setup**: Task toggle (`exam` / `generic`), Paper name, QUE / SOL PDFs (upload or server pick via the unified selector), "Auto-deskew scans" + collapsible "Pre-process scans" (`pre_rotate`, `split_mode`, `mode1_pages_per_student`, `f_*`), optional **Pages** (1-based source-PDF range, before A3 split), **Load PDF** (`POST /stage`). Exam staging defaults both versions to ENO in `meta`; the real import versions come from Step 3. There is no agent checkbox here — Load PDF only rasterises.
- **Step 2 — Bounding boxes**. The normal path is **Detect questions** then (for structured papers) the part split; the AI agent is a separate, experimental full-auto run.
  - Top row: LLM endpoint (+ Run in parallel for cloud endpoints), **Crop width** (`#cropWidthSel`, default `PDF_IMPORT_WIDTH_MODE_DEFAULT`; see [Crop width mode](#crop-width-mode)), and **Split questions into parts** (`#splitPartsChk`, exam; default from `split_parts_default`).
  - Buttons: **Detect questions** (`#btnRunDetect`; the label reads **Detect questions + parts** while Split is ticked, because pass 1 finishing then auto-runs `startSplitDetect`), **Detect parts** (pass 2 on the remaining whole-question boxes), Stop, Start over, Discard. A status line (`#frameStatus`) says per side how many pages have a printed frame and what Crop width will do with them.
  - **Advanced** (collapsed `<details>`): detection method, custom prompt + instruction, debug, and the box axis order of the selected endpoint (`#coordOrderHint`).
  - **AI agent strip** (exam only, small button + "Experimental" badge): outlines / locates / splits / verifies and **replaces** the plan; it never auto-starts on load.
  - Detection is optional — after Load PDF the page skeleton appears immediately for manual drawing. When detection runs, page cards render up-front with a "detecting…" badge and fill in as each `page` event arrives (`fillPageCard`).
  - Page card header: **Add box ▾** (question / part / stem — see [Review UI rules](#review-ui-rules-client-side-templatesadmin_pdf_importhtml)), **Re-run ▾** (the dropdown holds the per-page method and endpoint for `/redo-page`), **Re-split page**, **Renumber from here**, **Frame**. In the box list: edit the label (`3` / `3a` / `23-24`), row **+ ▾** (add a stem / part / sub-part to that question), Delete key, per-question **Re-split** / **Unsplit**, click a crop to enlarge (`showCropPreview`). Grey = stem, amber = part. Download processed PDF per side.
- **Step 3 — Import**: exam → version selects (both default to ENO), overwrite, trim whitespace, **Import to database** (`startCommit()` POSTs the edited plan to `/plan`, then opens the commit SSE with the live `paper`, `que_version`, `sol_version`, `overwrite`, `trim_white`). Generic → **Download all as ZIP**. Because commit re-reads the Step 1 paper and Step 3 controls, one reviewed plan can be imported repeatedly (e.g. import as ENO, switch to EN, import again). Changing the subject after staging is rejected.

### Tasks: exam vs generic

`task=exam|generic` is persisted as `meta['mode']`.

- **Exam paper** (default): QUE / SOL detection → `QUE` / `SOL` IMG assets. QUE and SOL may target different versions (`iter_commit(..., versions={'que':..., 'sol':...})`). **Custom detection prompt** (Step 2 checkbox + instruction, persisted at detect time): borrows the context-free generic prompt while still importing as exam assets — `detect_page(..., generic_prompt=True)` returns exam-shaped boxes with `qno=None`, and `iter_detect._finalize_detect` assigns 1..N per side in reading order; the UI re-sequences with `renumberAllSequential` (also after a per-page re-run).
- **Generic extraction**: no exam context, no paper / subject / DB. A free-text `instruction` drives `build_pdf_generic_system` / `build_pdf_generic_user_text` + `parse_generic_boxes` → `{label, box}`. Review uses a label textbox per region (no qno cascade). Only `llm` / `refine` methods (`segment` collapses to `llm`). Output is `POST /export-zip`.

### Two-pass part split

Pass 1 is unchanged: one box per numbered question (range labels `23-24` allowed; do **not** split `(a)(b)(c)` here). Pass 2 is opt-in (`#splitPartsChk`, seeded by `Subject.split_parts_default`):

1. UI POSTs the current plan to `/plan`, then opens `/split-detect` SSE.
2. For each whole-question group, the server crops that region (`pad_frac=0`, `trim_white=False`), runs `detect_parts` (crop-relative 0–1000), maps boxes onto the page with `full_width_child_box` (vertical extent from the model, **left/right edges inherited from the parent box** so stem and parts stay aligned and respect the side's uniform width), and replaces the group with stem + lettered children (keeping `source_*` so Unsplit can restore).
2a. **Stem fill** (`_split_one_group`): models sometimes fold the stem into part (a) or skip it. When the reply has lettered parts but no `stem`, and there is a printed strip between the parent's top and the first part's top, a stem child is inserted for that strip (label = the parent number, `source_*` kept, logged as "stem added from the text above the first part"). Guards, all required: QUE side only; the parent's **first** page only (on a continuation page the strip above belongs to the previous part); the parent is a plain number or a range (never a nested part like `4d`); the strip is at least `STEM_FILL_MIN_HEIGHT` (2% of the page) tall; and `pdf_layout.has_ink` finds printed content in it (the leftmost 8% is skipped so the question number alone does not count; no NumPy → no fill). The pass-2 QUE prompt also asks for the stem first ("everything printed above part (a), apart from the question number, is the stem"). `split_question_png(..., fill_stem=True)` applies the same fill on the IMG Split page; the split route passes `fill_stem=False` for a question that is itself a part.
2b. **Range split** (`31-32`, questions sharing one stimulus): pass 1 boxes the whole range as one region. Pass 2 calls `detect_parts(range_span=(31, 32))`, which uses the range prompts (`PDF_PART_RANGE_SYSTEM` / `PDF_PART_RANGE_USER` / `PDF_PART_RANGE_JSON_CONTRACT`) and parses labels with `hierarchy.normalize_range_box_label` (`stem`, or a number inside the range; letters and other numbers are dropped). The result is the range stem `31-32` plus child questions `31` and `32` (role `question`, `source_label = 31-32`); commit's `ensure_question` nests them under the range. Stem fill applies (the strip above the first question). A range is **not** sent to pass 2 when one of its questions already has its own box that was not split from it (`range_has_own_questions`: pass 1 boxed `31` / `32` separately, or `31` was since split into lettered parts); the log says so. `expected_labels` are ignored for ranges.
2c. **Shared blocks** ([ADR-015](../decisions/ADR-015-shared-blocks.md)): text printed **between** parts (ICT 2025 P1B Q7: the SS table before (c)). The QUE prompt asks for it as `intro-c` (`intro-diii` inside a part); `normalize_part_box_label` maps `intro-c`, `before (c)`, `~c`, `3~c`, `d~iii` to the block label, so the item becomes `7~c`. Independently of what the model calls it, `reclassify_mid_stems(children, parent_label)` runs after the page loop (QUE, non-range parents): a `stem` box that sits below a part on the same crop page, or on a later crop page of the question, and is followed by a part becomes the block before that part (`7~c`), or that part's own intro when a sub-part follows (`7c` before `7ci`). A `stem` followed by (a) stays the stem (a preamble spilling onto the next page). A box created by stem fill is never reclassified. On **SOL** a block label folds into the stem (marking schemes have no shared text). `split_question_png` applies the same rule to crop-relative labels (`_reclassify_relative_stems`). `expected_part_labels_for` and `compare_parts` ignore blocks; the agent never sets `depends_prev` on one.
3. Empty / no-parts replies keep the original whole-question box (a range with no numbered question found is "kept as one box"). A pass-2 `LLMError` (typically a read timeout at `PDF_IMPORT_LLM_TIMEOUT_SECONDS`) is retried once before the group is reported as `error` and kept whole.
3a. `parallel=1` (same "Parallel" tick as pass 1; honoured only for cloud endpoints with `max_concurrency > 1`) fans one side's crops across `run_parallel`. QUE completes and is merged before SOL starts so SOL `expected_labels` see the split QUE plan; plan mutation stays on the consumer thread.
4. SOL uses QUE labels as `expected_labels`; QUE receives them too when the agent supplies `expected_by_parent` (outline part tree). `detect_parts(extra_note=...)` prepends a repair note (agent).
5. `labels` csv re-splits one parent (Re-split button). Unsplit merges children back using `source_box` / `source_page`. `_replace_group` removes the parent, its descendants and anything with `source_label == parent`, so re-splitting `4d` leaves `4`, `4a`… intact; a range parent replaces itself and the questions split from it, never separate pass-1 boxes. With a `labels` filter, a question split from a range that is also in the filter goes with the range (`_split_parent_labels`), so the two results never race over the same boxes.
6. **Nested parts**: the pass-2 contract asks for a part's own introduction as the letter alone (`d`) and its sub-parts as `di`, `dii`; `compose_part_label` yields `4d`, `4di`. No special "nested stem" object exists.
7. **Roles are derived** from the label set on every save path (`apply_derived_roles` → `hierarchy.derive_roles`): `5` is a `stem` because `5a` exists, `5d` is a `stem` because `5di` exists, a labelled leaf is a `part`, a bare number/range with no descendants is a `question`, and a block (`7~c`) is always a `stem`. The browser mirrors this in `deriveRoles(kind)` so typing `4d` + `4di` in the Q inputs turns `4d` grey (stem) live. JS grammar mirror: `parseLabel` (accepts `7~c`, rejects `~a` / `~i`, `~ci`, range + path; returns `isBlock`), `partSegments`, `partSortKey` / `cmpKey`, `blockCovers`, `labelIsAncestor(p, c, labels, ends)` (block-aware: `7~c` is the ancestor of `7c` / `7d` unless a later block `7~e` covers them, or the block's end excludes them), `effectiveBlockEnd`, `blockEndChoices`, `planBlockEnds`. A block row shows a purple **shared** chip and reads "Q7 before (c)" (", (c) only" / ", up to (d)" with an end); Re-split / Unsplit and the row + are hidden on it. A QUE block row has an **Ends** dropdown (next block / end, or one of the same-level parts from its anchor up to the next block) stored as the item's `block_end`; `deriveRoles` passes it through, and `iter_commit` calls `hierarchy.set_block_end` on the committed block (QUE only; a plan without an end never clears an end already in the DB). **Add box ▾ → stem** drawn below a part of the same question is labelled as the block before the next part (`blockLabelForDrawnStem`).
8. **Manual editing** (review step): every exam row has a **+ ▾** menu that adds a stem, the next part or a sub-part to *that row's question* with the same x-span (never a new question; rules under [Review UI rules](#review-ui-rules-client-side-templatesadmin_pdf_importhtml)), the page card's **Add box ▾** draws a new question, part or stem (rules under [Review UI rules](#review-ui-rules-client-side-templatesadmin_pdf_importhtml)), the Delete / Backspace key removes the highlighted box, and the role chip is recomputed rather than typed. `depends_prev` on an item is a toggle in the row and becomes `Question.needs_prev_parts` at commit (parts with a parent only).

The IMG Split-into-parts page reuses pass 2 via `split_question_png` (default `find_parent=False`) on the **staged stitch**: `detect_parts` + `full_width_child_box` with one `LLMError` retry. If QUE has several images (Combine-reconstructed part crops, a multi-page WHOLE, …) they are stacked first; a single image is used as-is. Progress is SSE (`GET /admin/questions/<id>/split/detect`). `find_parent=True` adds pass 1 for a full exam-page scan only. Do not run `detect_parts` on each source PNG as if it were a paper page, and do not run `detect_page` on an already-cropped library QUE.

### Multi-page questions

The model sees one page at a time. A question tail spilling onto the next page is reported as a page-top region flagged `continues_prev` (the page above flagged `continues_next`). `iter_detect` keeps these transiently as `_cp` / `_cn` on plan items; `_finalize_detect` runs once after ALL pages are collected: for custom-prompt runs it numbers 1..N per side in reading order `(page, box top-Y)`; for standard runs it calls `_stitch_continuations(plan)`, which walks each side in reading order and lets a page-top continuation inherit the qno of the box before it (only across a page boundary; chains resolve because processing is ordered). On a **frameless** page the continuation also inherits the head box's **x1/x2** (the model otherwise boxes only the indented body). On a **framed** page with `frame_snap=1`, `snap_boxes_to_frames` runs after stitch so the per-page frame wins over that inherited x — see [Horizontal extent (x1/x2) chain](#horizontal-extent-x1x2-chain). This is independent of the order parallel detection returns pages. The flags are stripped before `plan.json` is written. The review UI mirrors it with `stitchContinuations()` (in `finishDetect` and after per-page re-run). At commit, same-`qno` parts become one multi-part IMG asset (`stitch=False`).

### Detection methods

`detect_page(config, png_path, atype, image_max_dim, method='llm', mode='exam', instruction='', generic_prompt=False, expected_labels=None, timeout=None)` → `(boxes, raw_text)`. `timeout` overrides `llm_timeout()` (only `/redo-page` passes it, via `detect_single_page(timeout=...)`; the agent's reconcile step keeps the import timeout). `expected_labels` (agent) fills `{{expected_note}}` in the exam prompts with the question numbers the outline expects on the page; `iter_detect(expected_by_page=..., page_filter=...)` and `detect_single_page(expected_labels=...)` pass it through. Plain runs leave it empty. Exam boxes: `{qno: int|None, label: str, box: [x1,y1,x2,y2] fractions 0..1, continues_prev, continues_next}`; generic boxes: `{label: str|None, box}`. `DETECT_METHODS = ('llm', 'refine', 'segment')`. `_check_method_available` fails fast with one SSE error when `refine` / `segment` are requested without NumPy. `shrink_sides = (atype == 'QUE')` — SOL keeps full width so right-hand marking notes survive. CV runs on the high-res PNG (`load_gray`); the LLM sees the downscaled copy (`prepare_image`, `LLM_IMAGE_MAX_DIM`); `_sent_image_size` reports the dims the model saw so pixel-range replies can be normalised.

- `llm` (default; no NumPy): `build_pdf_box_system` / `parse_question_boxes`. QUE prompt = tight box excluding answer space and margins but keeping the marks annotation (`(4 marks)`); SOL prompt = full solution including right-hand notes.
- `refine`: LLM boxes, then `pdf_layout.refine_box(gray, box, shrink_sides, grow_frac=PDF_IMPORT_REFINE_GROW_PCT/100, pad_frac=PDF_IMPORT_ASSIST_PAD_PCT/100)` expands into a search window then snaps to printed content via projection profiles (recovers chopped text / marks / figures, drops blank margins). A refine failure keeps the LLM box.
- `segment`: the model returns only `{qno, y-start}` anchors (`build_pdf_anchor_system` / `parse_question_anchors`), and `pdf_layout.segment_page(gray, anchors, shrink_sides, pad_frac)` derives boxes from the whitespace gap to the next anchor. Assumes a single column.

Every prompt builder receives `endpoint_id=config.id` so per-endpoint prompt variants apply.

### Horizontal extent (x1/x2) chain

DSE answer books print a rectangle on every page. Scans drift left/right between pages (odd/even booklet pages differ — e.g. left rail at 0.052 vs 0.087 of page width on ICT 2023 P1B), and the LLM boxes only the indented body on continuation pages, so per-question x-extents never lined up. "Uniform width" (widest box, left-anchored to each box's own `x1`) could not fix that. The printed frame is the per-page fact; x is resolved in this order:

1. **LLM box** — `detect_page` / pass-2 `detect_parts`. `_DEFAULT_PDF_QUE_BOX_SYSTEM` tells the model the left edge must be the numbered margin / inner frame edge, not the indented body.
2. **Stitch inherit (frameless only)** — `_stitch_continuations` copies the head question's `x1/x2` onto a continuation. Skipped in effect when the next step runs.
3. **Frame snap** (Crop width = Auto) — `apply_frame_snap(plan, meta, config)` is the single convergence point for every detection path: `iter_detect` (`/detect`, agent locate), `iter_split_detect` (`/split-detect`, agent split + repair rounds) and `/redo-page` all take `frame_snap` and call it **after** stitch (not in generic mode). The UI sends `frame_snap=1` on all three whenever Crop width is Auto (`frameSnapActive()`), and its own `stitchContinuations()` leaves x alone on framed pages, so a Re-run / Re-split page can never un-snap a continuation. `snap_boxes_to_frames` does the per-side work. `frame_x_extent(frame, inset_frac)` → `(x1, x2)` = rails inset by `PDF_IMPORT_FRAME_INSET_PCT/100`; y is untouched. The saved plan then matches the review UI.
4. **Review uniform width** (Crop width = Auto on frameless pages, or Uniform everywhere) — every box on a side gets the widest box's width, keeping its own `x1`. Framed pages are excluded in Auto mode.
5. **Commit `FrameCropper`** — a box is "snapped" when its `x1/x2` sit within `tol=0.006` of the frame's inner extent. Snapped crops use `crop_page(..., trim_axis='vertical')` (white-trim never re-narrows them) and, when `PDF_IMPORT_FRAME_NORMALISE_WIDTH` is on, are resampled (LANCZOS, ≤15% change) to the paper's median frame pixel width. Hand-widened boxes are cropped exactly as before. `iter_commit`, the `whole_source_crops` path, and `export_zip_bytes(..., inset_frac, normalise)` all go through it.

Detection and storage of the frame itself:

- `pdf_layout.detect_page_frame(gray)` (NumPy-only): column/row scores = minimum dark fraction over 3 bands of the page (a full-height rule scores, text does not); thin runs only; a vertical rail is accepted only if a horizontal rule starts/ends at it (perpendicular partner) — rejects scanner shadows. Returns `{left, top, right, bottom}` fractions (inner edges), `None` per rail if unconfirmed.
- `pdf_import.detect_frames(kind_dir, pages)` runs it per staged page at **stage time**. `consolidate_frames(raw)` consolidates per paper: paper width = median of pages with both rails; a page missing one rail gets it from the other + width; a page with none inherits same-parity page medians, else overall median; if <40% of pages show a frame the paper is frameless (all `None`). Result: `meta[kind]['frames']` aligned with `pages`, each entry `{'box':[x1,y1,x2,y2], 'source':'detected'|'inferred'|'manual'}` or `null`.
- `ensure_frames(token, meta)` lazily computes and saves frames for staging dirs created before this existed (called by detect, commit, export, `set_manual_frame`).

See [ADR-011](../decisions/ADR-011-page-frame-crop-anchor.md).

### Crop width mode

One select (`#cropWidthSel`) decides the left / right edges of every box; it replaced the separate "Snap boxes to page frame" and "Uniform width per side" checkboxes, whose combinations were hard to predict. Priority is **printed frame > uniform width > model**:

| Mode | Framed pages | Frameless pages | Server `frame_snap` |
|---|---|---|---|
| `auto` (default) | x from the frame (dashed green guide; horizontal handles hidden) | widest box's width on that side, each box keeps its own `x1` | 1 |
| `uniform` | widest box's width (frame ignored) | same | 0 |
| `model` | the model's own x | same | 0 |

Auto suits both DSE answer books (framed) and frameless MC papers, where the model's tight boxes would otherwise give every question a different width. Generic mode has no frames; Load PDF forces `model` there. The default comes from `PDF_IMPORT_WIDTH_MODE_DEFAULT`; Start over resets to it. Uniform width grows only (monotonic), is recomputed non-lossily after each streamed page (`enableUniformWidth(kind)`), and re-broadcasts when one box's width is resized (`applyUniformWidthToAll`); moving a box does not. Switch to `model` to fine-tune single boxes. See [ADR-014](../decisions/ADR-014-crop-width-mode.md).

### Coordinate convention

Coordinate handling is the primary failure mode. The prompt pins an explicit 0-1000 integer grid with top-left origin and a worked example. The axis order is not hardcoded: `build_pdf_box_system(atype, coord_order)` / `build_pdf_box_user_text(atype, coord_order)` fill `{{box_array}}` / `{{box_corner}}` / `{{box_example}}` (contract) and `{{box_pairs}}` (user turn) from `pdf_box_order_vars(coord_order)`, so what the model reads matches the parser. `detect_page` and `detect_parts` take the order from `llm_client.box_coord_order(config)` and pass it to both the builders and `parse_question_boxes` / `parse_part_boxes(text, img_w, img_h, coord_order)` (via `_normalize_box`):

- Axis order: `xyxy` (Qwen and most models) or `yxyx` (Gemma / Gemini / PaliGemma — vertical first). The endpoint's **Box axis order** (`LLMConfig.box_coord_order`, set under Admin → LLM Endpoints) wins; blank inherits `PDF_IMPORT_COORD_ORDER`. So a Gemini endpoint and a Qwen endpoint can be used side by side without flipping a global setting. The same helper feeds the PDF tool's region scan (`toolbox/pdf.py`) and the figure-bbox pass in MD generation (`ai_tools._embed_figures`). The import page shows the effective order for the selected endpoint under Advanced.
- Range (auto): max ≤ 1 → fractional; max ≤ 1024 → /1000; else raw pixels divided by the downscaled dims the model saw; else /max.

Debug: `detect?debug=1` (or `redo-page` body `debug: true`) logs each page's verbatim reply and attaches `raw` to the page event; the UI's Debug checkbox shows it in the console and a per-page collapsible. Use it to confirm the model's number range and axis order before changing the endpoint's Box axis order.

### Staging and rasterisation

- Staging dir: `<SYSTEM_PATH or OUTPUT_PATH>/.pdf_import/<token>/` holding `meta.json` (`mode`, `subject` / `source` / `year` / `paper`, `que_version` / `sol_version` / `version`, `custom_prompt`, `instruction`, `deskew`, `pre_rotate`, `split_mode`, `mode1_pages_per_student`, `filters`, `page_range`, `created_at`, per-kind `{filename, pages: [{index, filename, width, height}], frames: [{box, source}|null, ...]}` — `frames` aligned with `pages`), `plan.json`, and `que/` / `sol/` (`source.pdf` + `page_NNNN.png`, 1-based). `token = uuid4().hex`, validated by `_TOKEN_RE = ^[0-9a-f]{8,40}$` before any filesystem join. `cleanup_old()` (called on every `stage`) purges dirs older than 6 h; Discard removes one immediately. `save_meta` writes atomically via `.tmp` + `os.replace`. `ensure_frames` fills a missing / length-mismatched `frames` list on old tokens.
- `rasterize_pdf(pdf_path, out_dir, width_px, deskew, pre_rotate, split_mode, filters, workers, mode1_pages_per_student, page_range)` delegates to `app/pdf_tools.py`: `split_descriptors` → optional `parse_page_range` filter on **source** page indices → per-fragment op chain (`build_op_chain(pre_rotate, frag_ops, filters)`) → `rasterize_page` + `apply_ops`. The legacy `deskew` flag is merged into `filters['deskew']`. Splitting yields more staged PNGs, renumbered contiguously; downstream per-page detection is unaffected (Mode 1 drops padding slots such as page 8 of a 7-page booklet). `page_range` is applied before A3 split, so `1-4` keeps PDF pages 1–4 (both halves if split is on). Out-of-range numbers on a shorter PDF are skipped; a spec that matches nothing raises `ValueError` (stage → 400).
- Parallel rasterisation: `workers` from `PDF_IMPORT_RASTER_WORKERS` (default 4) capped by `os.cpu_count()`; `workers <= 1` or a single page keeps the sequential loop. Each worker opens its OWN `fitz.open(pdf_path)` — never share a `Document` across threads. Output is written by index so `pages` stays in reading order. A render failure re-raises and aborts staging.
- Deskew (`pdf_layout.deskew_image`): projection-variance angle sweep ±6°; silently skipped with a warning when NumPy is missing. Stored as `meta['deskew']`.
- Server picks: `_resolve_server_pdf(rel, root_id)` — root-aware via `RootRegistry(current_user).resolve(root_id)` (Shared / personal / Storage), or legacy relative to `PDF_SOURCE_PATH` when `root_id` is blank; must end with `.pdf` and pass `storage.safe_join`. Returns a duck-typed `_ServerPDF` (`.filename`, `.save(dest)` copies the file) so `stage` treats it like an upload.

### Paper-name guess

`guess_paper_name(config, pdf_path, filename, subjects, image_max_dim)` rasterises page 1 at width 1700, downscales via `prepare_image`, sends `build_pdf_paper_name_system` + `build_pdf_paper_name_user_text(filename, subjects)`, parses `parse_paper_name` → `(paper, confidence)`, and re-validates through `parse_paper_prefix` (invalid → `None`). The endpoint is `_pdf_default_endpoint()`: `PDF_IMPORT_DEFAULT_LLM` (vision-only) → `EXPLAIN_DEFAULT_LLM` (vision-only) → first enabled vision endpoint.

### Commit

`_group_plan(plan)` groups by `(kind, label)` ordered by integer prefix then depth (stems before parts). Items with no label or a malformed box are skipped. For each group: `ensure_question` (QID `{subj}_{source}_{year}_{paper}_{token}`, committed immediately so a later crop failure does not lose it); if `slot_has_img(question.id, atype, version)` and not `overwrite` → `skip`; else, for a **root** QUE that pass-2 split, `whole_source_crops` collects unique pass-1 `source_box` pages and `replace_img_assets(..., 'WHOLE', ...)` writes the unsplit original (nested stems and range stems return no crops); then `crop_page` every part and `replace_img_assets(question, atype, version, imgs, stitch=False, source_path)` (atomic; deletes existing IMG rows first — that IS the overwrite path; fires the DOC-thumbnail lifecycle). Exceptions roll back and emit `error`. SOL: exact QUE label match; unmatched lettered SOL skipped; leftover whole-question SOL attaches to the stem. There is no WHOLE-SOL.

`crop_page(png_path, box, pad_frac, trim_white, whiteness_threshold, min_px=8, trim_axis='both')`: pads by `pad_frac` (= `PDF_IMPORT_CROP_PAD_PCT / 100`, the "safety margin"), crops, raises `ValueError('degenerate crop box')` below `min_px`; when `trim_white` is on, tightens to non-white content (threshold `THUMBNAIL_WHITENESS_THRESHOLD`, keeps an 8 px border; content is never removed, so SOL side-notes survive). `trim_axis='vertical'` trims only top/bottom — used for frame-snapped boxes so white-trim cannot re-indent a continuation. `trim_white` is a per-run toggle: checkbox default = `PDF_IMPORT_TRIM_WHITE_DEFAULT` (OFF) → `&trim_white=` on the commit URL → `iter_commit(..., trim_white=)`. OFF = the crop respects the selected box exactly (plus safety margin); ON = tighten to content. Commit and ZIP go through `class FrameCropper(meta, inset_frac, pad_frac, trim_white, whiteness, normalise, tol=0.006)`: snapped boxes use vertical trim + optional width normalise; hand-widened boxes crop as before. `export_zip_bytes` always uses `trim_white=False` but still constructs a `FrameCropper` for width normalise.

### Review UI rules (client-side, `templates/admin_pdf_import.html`)

- **Questions are roots.** Reading order within a side = `(page, box top-Y)`. A question's root is its number prefix or range (`rootOf`: `4` for `4` / `4a` / `4bii`, `23-24` for a range). Every renumber moves a whole question: each box with that root (stem, parts, continuation pages) and its `source_label` (`setItemRoot` / `withRoot`: `4a → 5a`, `23-24 → 24-25`). A split range is one unit: `groupRootOf` maps a child question (`31`, `source_label = 31-32`) to its range, and `setItemRoot` shifts such a child by the range's offset (`31-32 → 30-31` moves `31 → 30`, `32 → 31`). The renumber paths call `groupRootOf(it, kind)`, which also maps a single-number box inside a range box on the same side **without** `source_label` (pass 1 boxed the stimulus `27-28` and the questions `27`, `28` separately, so pass 2 never split them). The row + menu calls it without `kind`, so such questions still get their own stem / part options.
- **Add box ▾** (exam; `startAddMode(card, role)` sets `card._addRole`, read and reset by `finishDraw`). Drawn boxes are frame-snapped / uniform-width-conformed first.
  - *Question* (the main button): label = previous root + 1 (`renumberAfterInsert`). Later questions shift +1 only while they would clash, so a gap (a question the model missed) absorbs the insert instead of renumbering the rest of the paper.
  - *Part*: the target question is the box on this page that contains the new box's top (smallest such box), else the nearest numbered box above it in reading order, possibly on an earlier page (`targetRootFor`). Label = the next top-level letter after its existing parts (`nextTopLetter`: `4a → 4b`; roman-only `6i, 6ii → 6iii`). For the **first** part drawn inside the whole box `4`, box `4` is trimmed to end at the new part's top (it becomes the stem), and both boxes get `source_label` / `source_page` / `source_box` = the original, so **Unsplit** restores it (no trim when the part starts at the top of `4`). Later parts copy a sibling's `source_*`. Never renumbers other questions. A range target or no question above falls back to Add question.
  - *Stem*: label = the bare number. The target is the question whose part is the next box below (`stemTargetBelow`, when that question has no stem on the page), else as for Part. If the question already has a box labelled with its number on this page, that box is selected and the log explains instead of adding a duplicate.
- **Row order**: each page card's box list runs top to bottom by box top. `addBoxDom` inserts every row before the first row whose box starts lower (`row._item`). Plan order is not reading order: `/split-detect` (`_replace_group`), Unsplit and Add box ▾ put new items at the end of the plan. Rows are not re-sorted while a box is dragged.
- **Job strip** (`#jobStrip`, sticky under the `sticky-top` navbar; `syncStripTop` sets `top` to the navbar height): status badge, what is running with count and a thin bar, the latest log line (coloured by type), **Stop** while a stoppable job runs and **Log** (scrolls to the log). It mirrors `setStatus` / `showProgress` / `updateProgress` / `appendLog` / `setProgressLabel`. `setRunning(false)` marks the job "— finished" unless `setStatus('Stopped' | 'Error')` already marked it "stopped" / "failed" (`stripEnded`). Load PDF and per-page Re-run, which have no progress events, call `stripStart(label, true)` (indeterminate bar) and `stripEnd`. It appears with the first job and stays until Reset. `scroll-margin-top` keeps scrolled-to cards clear of it.
- **Keyboard**: Delete / Backspace removes the selected box (page handler). Arrow keys nudge the last clicked box, and H hides the magnifier while dragging. Both come from `OQBBboxEditor` (see [../frontend/conventions.md](../frontend/conventions.md#bounding-box-editor-oqbbboxeditor)); a nudge is a `move`, so joined edges do not follow.
- **Row + ▾** (exam; `buildRowAddMenu` → `rowAddOptions` → `addToQuestion`): adds to the row's own question, on the row's page, with the neighbour box's `x1/x2`, so only the vertical edges need adjusting. Never adds a new question (that is Add box ▾) and never renumbers. The question's *area* on the page = its boxes there plus the pre-split original (`source_box` on that page).
  - *Stem* — at the top: the free strip between the area top and the first box when it is ≥ `ADD_STRIP_MIN` (2% of page height), else the first box's top third (`rowAddSlot`). Disabled when the question already has a stem box (any page).
  - *Part Q4c* — at the bottom, label `nextTopLetter`: the free strip below the last box, else the last box's bottom half.
  - *Parts Q4a + Q4b* (whole question only) — the box is halved into `4a` / `4b`, no stem.
  - *Sub-part* (leaf parts only) — `4b → 4bi` takes the lower half of `4b` (the top stays as its lead-in); `4bi → 4bii` goes below `4bi` (the free strip up to the next box, else `4bi`'s bottom half). Offered only when the label is free.
  - A **whole question** turned into stem + parts: Stem relabels the remainder `4a`; Part leaves the top as stem `4`. Every box with that root on every page that has no `source_box` gets `source_label = 4`, `source_page` = its page, `source_box` = its current box, so Unsplit and the whole-question crop at commit restore all pages. Its bare-number boxes on **later** pages take the label of the part that ends this page (they continue it).
  - **Joined edge**: when the new box is cut out of the neighbour (no free strip), the pair is stored in `joinedEdges` (`"upperUid>lowerUid"`). Resizing either box across that line moves the other's edge too (`applyJoinedEdges`, wired through `constrainBoxFor`; each box keeps ≥ `JOIN_MIN_H`). The join only acts while the edges still meet, so moving a box ends it. Not persisted (client-only, like `_uid`).
  - Ranges, questions split out of a range (`groupRootOf ≠ rootOf`) and unlabelled rows show a muted + that explains why in the log.
- **Delete** (`renumberAfterDelete`): cascades only when the deleted box was the **last** box with its root (deleting a part, a stem, or one page of a multi-page question shifts nothing). Then later questions shift −1 across the consecutive run that follows; the first gap or out-of-order number stops it.
- **Renumber from here** (page card button, and the banner) → `renumberFromPage(kind, page)`: numbers every question from that page to the end of the side consecutively, continuing from the last question before the page. Consecutive boxes with the same root are one question; parts follow it; a range keeps its width. A box starting a new page keeps the previous question's number only when it is that question continuing (`continuesFrom(prev, cur, kind)`): the persisted `cont` flag (set by stitch, by Unsplit on its later pages, or by the row's **Cont.** toggle), the model's transient `cp` / `cn` flags, the same `source_label` root, another question of the same range (`28` after `27-28` / `27`), or a part label of the same question (`4b` after `4a`). A **bare number repeated** at the next page's top (`29` after `29`) without one of these is a new question: it gets the next number and the log says so. With nothing before the page, the first question keeps its own number. Logs how many questions changed.
- **Cont.** row toggle (`buildContToggle`, inside `buildSplitActions`): shown only on the first numbered box of a page with a numbered box on an earlier page, and only when the labels do not already decide it (`continuesByLabels`). On = `cont: true` (continues Q*n* from the previous page); off clears `cont` / `cp` and the previous box's `cn`. It does not relabel; the log points to Renumber from here.
- Re-detecting a page (Re-run) replaces its boxes with the model's numbers and does not cascade; manual label edits and move / resize never cascade.
- **Numbering warning** (`updateOrderWarning` over `numberingIssues(items)`, exam only), per side in reading order:
  - *Drop* — a smaller integer prefix after a larger one (red banner). The first drop per side carries **Renumber … from page N**, N = the page of the larger number.
  - *Gap* — numbers between the side's first and last question that no box covers (a range `31-32` covers 31 and 32), e.g. "Q27–Q29 are missing between Q26 (page 8) and Q30 (page 10)". Each page between the two neighbours that has no boxes is named (with the error if its detection failed) and gets a **Re-run page N** button; otherwise **Go to page N**. A gap touching a page that is still detecting is not shown.
  - *Repeat* — the same label boxed twice on **one** page (commit joins same-label boxes into one image), or the same label at the top of the next page that is not a continuation by `continuesFrom` (no `cont`, not a part / split source). The cross-page row offers **Renumber from page N** (the later page) and points to **Cont.**
  Gaps / repeats alone make the banner amber. The first and last numbers are not checked (a page range may start mid-paper).
- **Failed pages**: a pass-1 page whose model call failed after the retry arrives as an `error` event with `page.failed` / `page.error`. The card gets a red border, a red **detection failed — Re-run** badge (error in its tooltip) and an explanation in place of "No regions"; the `done` message lists the failed pages. A successful Re-run clears it (`setPageFailed`).
- **Part split**: `#splitPartsChk` (default from `/stage` `split_parts_default`). Auto-runs pass 2 after pass 1 and when the checkbox is ticked with existing boxes. **Detect parts** re-runs pass 2 on remaining whole-question boxes. Per-question **Re-split** / **Unsplit**. Overlay: grey stem, amber part.
- **Page frame** (Crop width = Auto, exam): boxes on framed pages take `x1/x2` from the dashed green guide; the wrap gets `x-locked` (horizontal handles hidden); drawn boxes snap. Dragging a green rail POSTs `/admin/pdf-import/frame` and re-snaps that page. Each page card has a **Frame** button toggling "No frame" / "Add frame" (seeds from same-parity pages) and a badge `frame` / `frame (inferred)` / `frame (manual)`.
- **Uniform width** (Crop width = Auto on frameless pages, or Uniform): see [Crop width mode](#crop-width-mode). `conformWidth` is left-anchored (only the right edge moves).
- **Shared overlay editor**: never reimplement box overlays or a canvas painter. Mount `OQBBboxEditor`; mutate boxes through the host model then call `ed.restyle(item)`. See [../frontend/conventions.md](../frontend/conventions.md#bounding-box-editor-oqbbboxeditor).
- **Live magnifier / crop preview**: owned by `OQBBboxEditor` (`.pdf-magnifier`, `showCropPreview`). Hosts do not draw their own magnifier.
- "Run in parallel" (`updateParallelUI`) is shown only for cloud endpoints and appends `&parallel=1`.

## How LLM work is scheduled

Time is almost entirely **vision-LLM round trips**. Frame detect / snap / stitch are CPU milliseconds and are not why a run feels slow.

| Action | Vision calls (happy path) | What each call sees |
|---|---|---|
| **Load PDF** | 0 | Raster + optional deskew + `detect_page_frame` per page (NumPy). |
| **Detect questions** | 1 per staged page (QUE and SOL each count) | The full page PNG, downscaled to `LLM_IMAGE_MAX_DIM`. |
| **Detect / Re-split parts** | 1 per *page-crop of each parent question* | A tight crop of that question (or its continuation page), not the whole page. A 2-page Q5 = 2 calls. |
| **Re-run** (one page) | 1 | That page only. |
| **AI agent** | Outline + locate + split + verify (see below) | Mix of thumbnails, full pages, crops, and overlay-check images. |

**Pass 1 (`iter_detect` / Re-run).** Sequential on a local endpoint; cloud endpoints can fan out when Parallel is ticked (`kind==cloud` and `max_concurrency>1`). `iter_detect` retries the same page once on `LLMError` via `_call_with_llm_retry` (a timeout therefore costs up to 2 × `PDF_IMPORT_LLM_TIMEOUT_SECONDS` — 2 × 60 s by default — before the page is reported failed; a flaky local model can double a page). Every PDF-import `llm_client.chat` call (detect, Re-run, part split incl. IMG Split auto-detect, paper-name guess) passes `timeout=pdf_import.llm_timeout()`; `0` falls back to the endpoint's `timeout_seconds`. The agent's outline / verify calls (`pdf_agent.py`) keep the endpoint's timeout. `/redo-page` does not retry — the user is already re-running. After all pages: stitch continuations, then `apply_frame_snap` (rewrites x only; no extra model call).

**Pass 2 (`iter_split_detect`).** For each parent, `_split_one_group` writes a temp crop per page of that question and calls `detect_parts`. Children inherit the parent's x (`full_width_child_box`). Then stitch + frame snap. **Re-split page** still re-splits every *root* that touches the page, including its other pages, so a continuation is not cut in isolation.

**AI agent (`iter_agent`, ADR-010).** Always more calls than the two-pass wizard:

1. **Outline** — batches of `PDF_AGENT_OUTLINE_BATCH_PAGES` (default 6) page thumbnails (`PDF_AGENT_THUMB_MAX_DIM`). A 12-page paper ≈ 2 outline calls per side. Invalid JSON retries once.
2. **Locate** — `iter_detect` with `expected_by_page` from the outline; skips pages the outline marked empty. Missing questions get a second `detect_single_page`.
3. **Split** — same `iter_split_detect` as the wizard, with expected part labels from the outline.
4. **Verify** — up to `PDF_AGENT_MAX_REPAIR_ROUNDS` (default 2) visual checks *per question per page it occupies*. A failed check can trigger another full pass-2 of that question. Hard cap `PDF_AGENT_MAX_LLM_CALLS` (default 150).

A typical ICT P1B (12 QUE pages, 5 multi-part questions, no SOL) is roughly: wizard detect 12 + split ~12–20; agent outline 2 + locate 12 + split ~12–20 + verify 5×1–2 pages × up to 2 rounds. Frame snap does not add calls.

## Background work / SSE / threads

- `detect`, `split-detect` and `commit` are GET SSE streams (EventSource) run inside a pushed `app.app_context()` with `Cache-Control: no-cache`, `X-Accel-Buffering: no`. The dev server must run threaded.
- Detection re-fetches the endpoint inside the generator (`live_cfg`) and sets `live_cfg._batch = True` (opts into `service_tier_batch`).
- Parallel detection: the route inlines the same gate as `_ai_parallel` — on only when `parallel=1` AND `kind == 'cloud'` AND `max_concurrency > 1`; then `iter_detect` fans `detect_page` across `app.parallel.run_parallel`. Results are ingested on the consumer thread; `CANCELLED` results are skipped. Numbering / stitching is deferred to `_finalize_detect` so parallel completion order cannot change the outcome.
- Rasterisation uses its own `ThreadPoolExecutor` (`PDF_IMPORT_RASTER_WORKERS`), one `fitz` document per worker.
- Cancel registry `_PDF_CANCEL` is in-process: the cancel POST must reach the worker running the stream (same caveat as AI Tools and settings hot-reload).

## Gotchas

1. Detection, redo-page, split-detect, commit and guess-paper are gated on `AI_TOOLS_ENABLED` and need a vision-capable `LLMConfig` (SSE routes surface this as a single `error` + `done`). Staging, page images, plan save, processed PDF, ZIP export and discard work without AI.
2. Subject admins can only stage / import papers for their subjects; generic sessions are open to any admin.
3. Past-paper sources only (`DSE` / `CE` / `AL` via `PREFIX_PATTERN`); QB is out of scope. `section` / `level` remain null.
4. The LLM sees the downscaled page (`LLM_IMAGE_MAX_DIM`); crops come from the high-res page (`PDF_IMPORT_RASTER_WIDTH`). Boxes are fractional, so they are resolution-independent — but pixel-range replies are normalised against the downscaled size, not the raster size.
5. The box axis order changes both the prompt wording and the parse. It is per endpoint (`LLMConfig.box_coord_order`, blank = `PDF_IMPORT_COORD_ORDER`). If boxes look shifted or transposed, check the raw reply with Debug, then set that endpoint's Box axis order rather than the global setting. Always read it through `llm_client.box_coord_order(config)`; never read `PDF_IMPORT_COORD_ORDER` directly at a new call site.
6. `replace_img_assets` deletes the slot's existing IMG rows before writing — that is the overwrite path. The only guard is the `slot_has_img` skip when `overwrite` is off. That skip also prevents writing a missing `WHOLE` archive onto a root that already has QUE; upload the archive in the Edit modal or re-import with overwrite. Nested stems and range stems never get WHOLE.
7. NumPy is optional: `refine` / `segment` / deskew / `detect_page_frame` need it. Detect fails fast with one SSE error; deskew silently warns and skips; missing NumPy yields all-`None` frames and the rest of the pipeline behaves as before. `segment` assumes a single column — dense MC or note-heavy SOL pages can over- or under-merge; per-page re-run with `llm` is the escape hatch.
8. Never share a `fitz.Document` across threads; each raster worker opens its own.
9. `_finalize_detect` runs after all pages — custom-prompt numbering and continuation stitching are deterministic regardless of completion order; the old per-page numbering was order-sensitive. Re-detecting a single page (`/redo-page`) replaces that page's boxes and does not re-stitch server-side; the UI's `stitchContinuations()` handles it, then `applyWidthPolicy()` — **in that order** (stitch may copy the head page's x; the frame must win afterwards). An earlier build had them reversed and Re-run produced un-snapped continuations.
10. **Re-split page** (per-card button) collects the *root* labels (`rootLabelOf`: `source_label`, else the numeric prefix) of every box on that page and calls `/split-detect?labels=…`. The server re-splits each root as a whole via `original_group_parts`, so a question that continues from/onto another page is re-cut across all its pages — this page's parts are never re-cut in isolation, which would break the cross-page link.
10. Continuation flags `_cp` / `_cn` (browser `cp` / `cn`) are transient; what survives is `cont: true`, set on a box that `_stitch_continuations` / `stitchContinuations` linked to the previous page. Exam `plan.json` and `/plan` payloads are `{page, qno, label, box, role?, source_*, depends_prev?, cont?, block_end?}` with `role` always recomputed server-side. Generic stays `{page, label, box}`.
11. `trim_white` OFF is the default; the crop honours the box exactly plus `PDF_IMPORT_CROP_PAD_PCT`. ZIP export never trims but does apply the pad.
12. Commit uses the live Step 1 paper and Step 3 versions, not the staged ones (persisted back into `meta`); changing the subject is blocked. The same plan can be imported repeatedly under different versions.
13. Stage defaults `deskew` to on when the field is absent; the toolbox filter `f_deskew` also sets it. Both merge into `filters['deskew']`.
14. Staging dirs auto-purge after ~6 h on the next `stage` call; a stale token yields "Staging session not found or expired".
15. Uploads win over server picks for the same side; `root_id` blank means the legacy `PDF_SOURCE_PATH` root.
16. Exam labels are QNO tokens via `normalize_plan_label` / `parse_qno_token` — `3a` and `23-24` are kept, not first-digit-only. Pass-2 crop mapping must use unpadded crops (`pad_frac=0`) or part boxes drift. `split_parts_default` only seeds the checkbox; the live tick is what auto-runs pass 2.
17. `pdf_import_stage` already uses the module-level `Subject`. A late `from app.models import Subject` inside the function makes `Subject` local and crashes Load PDF with `UnboundLocalError` before rasterisation.
18. Never store or trust a model-supplied `role`; `derive_roles` is the only source. If a chip looks wrong, the label set is wrong.
19. The AI agent run (`/agent`) starts from `iter_detect` and therefore **replaces** the plan; manual edits made beforehand are lost (the wizard confirms first). The agent is **experimental**: it lives in its own Step 2 strip (**Run AI agent** after Load PDF), costs more model calls than Detect questions + parts, and does not auto-start.
20. `page_range` is 1-based source-PDF pages, shared by QUE and SOL, applied before A3 split. Junk or a spec that matches no pages is a 400, not a 500.
21. IMG Split-into-parts (`question_split.iter_detect_boxes`) stitches multi-image QUE first, then SSE pass 2 (`detect_parts` + `full_width_child_box`, one retry on `LLMError`) **once on the stitch**. Do not send each part-crop as its own page. Do not run pass 1 (`detect_page`) on an already-cropped question unless `find_parent=1`. The split page mounts `OQBBboxEditor` on the stitch — do not reintroduce a `<canvas>` painter.
22. `trim_white` would re-indent continuation crops (the body is narrower than the printed frame). `FrameCropper` trims **vertically only** for snapped boxes (`trim_axis='vertical'`).
23. Frames are detected at **stage time**; old tokens get them lazily via `ensure_frames` (detect, commit, export, `set_manual_frame`).
24. Odd/even booklet pages have different scan offsets — `consolidate_frames` uses same-parity medians before the overall median. If fewer than 40% of pages show a frame the paper is frameless.
25. Crop width priority is frame > uniform width > model, and it is one select (`cropWidthSel`). Do not reintroduce independent frame-snap / uniform-width toggles: their four combinations were what made tight, uneven crops on frameless MC papers. Client code asks `frameSnapActive()` / `uniformActive()`; the server only sees `frame_snap`.
26. Stem fill only ever adds a box; it never moves or relabels the model's parts. If a filled stem is wrong (e.g. a figure that belongs to part (a)), delete it or resize it — Unsplit / Re-split behave as for a model stem. The fill is skipped on continuation pages, SOL and nested parts by design; do not widen it without new tests in `tests/test_pdf_import_plan.py`.
27. `finishDraw` must read `card._addRole` before anything else and reset it. `OQBBboxEditor._finishDraw` turns add mode off (firing `onAddModeChange`) **before** calling `onCreate`, so resetting the role in `onAddModeChange` would lose it.
28. The renumber cascade shifts whole questions by root. A shift must go through `setItemRoot` so `source_label` follows; a stale `source_label` makes Re-split / Unsplit / `rootLabelOf` target the old number.
29. A range (`31-32`) must not go through the lettered-part path: `compose_part_label` rejects letters on a range and `normalize_part_box_label('31')` is `stem`, so a range crop sent to the normal prompt always came back "no lettered parts — kept as one question" (the bug before range split existed). Ranges use `range_span` end to end (`detect_parts` → range prompts → `parse_part_boxes(range_span=…)`).
30. The busy-button source (`lockPageJobs(sourceEl, …)`) may sit outside `#reviewBody` — Step 2's **Detect parts** does. `unlockPageJobs` restores every `.job-busy-src` in the document; scoping it to `#reviewBody` left "Splitting…" spinning after the split finished.
31. A failed pass-1 page is not an empty page. Keep the `error` event's `page.failed` / `page.error` and show it (`setPageFailed`); never render a failed page as "no regions", or the next questions look mis-numbered rather than missing.
32. The row **+** adds stems / parts only. It used to add `next_part_label` below the row, which on a whole question `4` meant a new question `5` with no renumber cascade. New questions go through **Add box ▾** (`renumberAfterInsert`). `unlockPageJobs` sets `disabled = false` on every `.split-actions button`, so a row control that must stay inert uses a style + explanatory click, not `disabled`.
33. When the row + turns a whole question into stem + parts, `source_*` must be set on **all** of that question's boxes, on every page, before shrinking. `unsplitParent` drops every box of the question and restores only boxes carrying `source_box`, and `whole_source_crops` builds the WHOLE image from them: a continuation box without it would vanish on Unsplit and be missing from WHOLE.
34. Box-list rows must go through `addBoxDom`, which places them by box top. Appending rows in plan order put split questions at the bottom of their page's list, because the server appends split children to the end of the plan.
35. Do not rely on `source_label` alone to keep a range and its questions together. A range whose questions pass 1 boxed itself (`27-28` + `27` + `28`) never reaches pass 2, so `27` / `28` have no `source_label`. Before `groupRootOf(it, kind)` checked for a range box on the same side, Renumber from here kept `27-28` and pushed `27 → 29`, `28 → 30`.
36. `/redo-page` is the only detection call without a retry, and the user waits on it. It uses `redo_timeout` (the longer of the import timeout and the endpoint's `timeout_seconds`), not the 60 s batch cap: one slow page (for example a dense cover page on a reasoning model) used to time out on every Re-run.
37. A page-top box with the same bare label as the box before it is ambiguous (a question spanning pages, or a repeated number after manual edits), and the labels cannot settle it. Only `cont` can. Plans staged before `cont` existed have no flag on their continuations: Renumber turns them into new questions, and the banner lists them as cross-page repeats so the user can press **Cont.**. Any new code that builds a continuation box (stitch, Unsplit, a future "draw tail" tool) must set `cont: true`.
38. A second `stem` on a question is **not** a continuation of the first. Before shared blocks, `compose_part_label('7', 'stem')` → `7` and `_group_plan` merged the SS table (printed before (c)) into Q7's QUE as page 2, so every surface printed it above (a). `reclassify_mid_stems` must run before `_group_plan` sees the children; do not move it after the merge. Rows imported before the fix are repaired per question from the Edit modal (Assets → layers icon → move page to a new block); see [question-hierarchy.md](question-hierarchy.md#shared-blocks-text-between-parts).
39. A DB-overridden `PDF_PART_QUE_SYSTEM` (AI Prompts page) does not contain the `intro-c` rule. Reclassification still catches the common case (a `stem` below a part); reset the prompt to default or add the rule by hand to get labels from the model too.
40. JS and Python sort blocks the same way: `~c` after `b`, before `c` (`partSortKey` / `part_sort_key`). Changing one without the other reorders the review list against the commit. The same holds for block ends (`blockCovers(…, end)` / `effectiveBlockEnd` / `labelIsAncestor(…, ends)` vs `hierarchy`); checked case-by-case against Python in headless Edge when they change.
